The landscape

One estate, three levels of control

Every option below builds agents that live inside Savino's own Microsoft 365 tenant. They differ in who builds them and how much control you get — not in where the data lives. Microsoft's own rule of thumb: prototype low, harden in the middle, productionise high only when the workload demands it.

Before you pick a tool

Two kinds of agent

Whatever tool builds it, a Microsoft 365 agent is one of two archetypes. The choice of archetype comes first; the build tool follows.

Configure Copilot

You give Copilot custom instructions, knowledge and actions. Copilot's own orchestrator and model do the reasoning. No extra hosting to run.

Strengths
  • Shortest path; nothing to host or maintain
  • Inherits M365 security, compliance and responsible-AI
  • Knowledge from SharePoint, OneDrive, Graph connectors, files, web
  • Actions via OpenAPI plugins and MCP servers GA Dec 2025
Limits
  • Can't choose the model or the orchestration logic
  • No proactive messaging; no non-Microsoft channels
  • Bounded by Copilot's fixed reasoning behaviour
For Savino: the natural start if the agent reads M365 knowledge and drafts replies — minimal moving parts. Build it in Agent Builder, Copilot Studio or the Agents Toolkit.

Extend with your own engine

You bring your own orchestrator, model, tools, memory and channels. Surfaces through Copilot Studio, Teams, web, mobile and custom apps.

Strengths
  • Full control of workflow, model choice and integrations
  • Proactive messages; reach beyond Microsoft 365
  • Plug in Azure OpenAI, Azure AI Search, custom tools
  • Low-code (Copilot Studio) or pro-code (SDKs / Foundry)
Costs
  • More to design, run and govern
  • Pro-code routes need developer skills in-house
  • Only warranted when the workload truly needs it
For Savino: escalate here only when orchestration, model choice, proactivity, out-of-M365 reach or deeper retrieval demand it — e.g. reading a non-Microsoft freight system of record. A Copilot Studio custom-engine agent gets most of this while staying low-code.

Our focus for Savino

The email agent — three build tiers in Copilot Studio

For Savino's triage-draft-reply workstream we build on the two generally-available tiers and treat the newest one as a future upgrade, never the foundation of a committed deliverable.

Autonomous agent + native email trigger GA

Trigger configured directly on the agent — no separate flow to maintain. It runs the moment an email lands. An Activity log records every action for audit. This is our primary build target.

Power Automate flow → topic GA

The classic pattern where we need flow-level control. The draft is intercepted at the "AI Response Generated" topic — exactly where the human-approval step is inserted instead of auto-sending.

Work IQ / MCP dynamic Outlook access PREVIEW

The newest layer: the agent is given a discoverable toolkit and reasons at runtime which tools to use — e.g. searching email history to contextualise a reply. Microsoft's own guidance keeps human review necessary for customer-facing output here. We demonstrate it, we don't build Savino's committed deliverable on it until it ships GA.

⚠︎ Rule we hold to: a committed deliverable is never based on a preview feature. Preview tiers are shown for direction only.

How we go live

Human-in-the-loop first — autonomy is a switch, not a rebuild

Every send ships in approve mode. As a reply path proves itself on real traffic, Savino flips that path to auto-send with a configuration change. The drafting work is identical either way.

Phase 0

Connect & classify

Agent reads, classifies and drafts into a review queue. Nothing is sent. Proves accuracy on real Savino mail while touching nothing live.

Phase 1

Assist

Agent drafts autonomously; a person approves every send. Knowledge sources the replies depend on are added.

Phase 2

Automate

Proven reply paths flip from "human approves" to "auto-send", one at a time, by configuration.

Try it — governance toggle per reply path

This is the real decision Savino makes per path. The execution path doesn't change — only who clicks send.
